# Практическая работа №2. Инструмент визуализации графа зависимостей для менеджера пакетов

## Этап 1: конфигурация

В ветке `stage1` программа читает INI, проверяет параметры и выводит их.

```powershell
.\run.bat
```

Проверка ошибок:

- `.\run.bat tests\bad_package.ini` - Имя пакета не может быть пустым
- `.\run.bat tests\bad_repository.ini` - Некорректный URL репозитория
- `.\run.bat tests\bad_test_mode.ini` - Некорректное логическое значение
- `.\run.bat tests\bad_output_file.ini` - Выходной файл должен иметь расширение .svg
- `.\run.bat tests\bad_ascii_tree.ini` - Некорректное логическое значение
- `.\run.bat tests\missing_repository.ini` - Файл тестового репозитория не найден
- `.\run.bat tests\nonexistent.ini` - Конфигурационный файл не найден

## Этап 2: сбор прямых зависимостей

В ветке `stage2` программа получает из PyPI прямые зависимости пакета
и выводит их с ограничениями версий. Пакет задаётся в `config.ini`.

```powershell
.\run.bat
```

## Этап 3: граф зависимостей

В ветке `stage3` программа строит граф в памяти с помощью DFS без
рекурсии, сохраняет версии и сообщает о циклах. Тестовый репозиторий
`tests/pypi_graph.json` использует формат ответов PyPI.

```powershell
.\run.bat
```

Проверка на тестовом репозитории:

- `.\run.bat graph_diamond.ini` — общая зависимость у двух пакетов.
- `.\run.bat graph_cycle.ini` — цикл между пакетами.
- `.\run.bat graph_self_cycle.ini` — зависимость пакета от самого себя.
- `.\run.bat graph_leaf.ini` — пакет без зависимостей.

## Этап 4: порядок загрузки

Программа выводит в консоль порядок загрузки пакетов: зависимости
идут раньше пакетов, которым они нужны. Этот порядок можно сравнить
с выводом `pip`.

## Этап 5: визуализация

Программа сохраняет изображение графа в SVG-файл, указанный в
`output_file` (по умолчанию `graph.svg`). При `ascii_tree = true`
в консоли дополнительно отображается дерево зависимостей.
